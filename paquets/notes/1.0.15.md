# YDZ OS 1.0.15 — Sécurité

**Sécurité** : la tour se verrouille sur ton téléphone et ton ordinateur, les failles trouvées à l'audit sont corrigées, et un contrôle réseau léger tourne toutes les heures.

> Installer après la 1.0.14. **À faire une seule fois à la main** (voir plus bas) : les versions suivantes, elles, arriveront toutes seules. Ton code PIN à 4 chiffres marche encore, mais l'interface te demandera d'en choisir un de 6 chiffres ou plus.

### Ajouté
- **Écran de verrouillage** sur téléphone et ordinateur : rien ne s'affiche ni ne se charge tant que le code n'est pas entré (pavé flottant, animation, vibration si le code est faux). L'écran de la tour, lui, n'est jamais verrouillé.
- **Verrouillage automatique** : la tour se reverrouille après un temps sans rien faire (réglable, 15 min par défaut) et quand l'app reste cachée trop longtemps. Bouton « Déconnecter tous les appareils ».
- **Contrôle réseau toutes les heures** (Réseau) : petit test de débit, latence, gigue, perte, passerelle et DNS ; courbe sur 24 h / 7 jours, alerte si Internet tombe ou si le débit reste faible, et consommation estimée par jour. Le test complet reste la nuit.
- **Confirmation d'appairage Bluetooth** : le code à 6 chiffres s'affiche dans l'interface avec un bouton « Oui, c'est le bon » ; plus rien n'est accepté tout seul.

### Modifié
- Les mises à jour de YDZ OS se lisent désormais dans les **fichiers du dépôt GitHub** (`paquets/index.json` + les .zip) et non plus dans les « Releases ». Notification, installation en chaîne et installation auto de nuit : inchangées.
- Nouveaux codes PIN : **6 à 8 chiffres** (l'ancien code à 4 chiffres continue de marcher, avec un bandeau qui invite à le changer).
- Le terminal web (ttyd) vérifie l'origine des connexions et limite le nombre de sessions.

### Corrigé
- Un appareil inconnu du Wi-Fi ne peut plus se faire passer pour un nœud de la tour.
- L'écran de la tour se recharge proprement après la mise à jour.

### Sécurité
- La tour **ignore les Pi non appairés** : un appareil doit prouver qu'il possède la clé de la tour avant que ses informations soient affichées ou qu'il reçoive un ordre.
- **Toutes les valeurs affichées sont échappées** et une politique de contenu stricte (CSP) est envoyée sur chaque page : un nom piégé ne peut plus exécuter de code dans l'interface ni sur l'écran de la tour.
- Les **ordres entre nœuds sont signés** en liant la machine visée, le chemin, le corps, un jeton à usage unique (anti-rejeu) et l'heure de la tour : une signature ne peut plus être rejouée ni réutilisée ailleurs.
- La **limitation des essais du code PIN** ne se contourne plus (compteur global, blocage progressif) et l'adresse d'un visiteur n'est crue que lorsqu'elle arrive par l'accès Tailscale.
- Les **sauvegardes sont chiffrées** (openssl AES-256) avec une phrase connue de toi seul, envoyées en SMB3 chiffré et signé ; les secrets re-créables (jeton local, clé d'extinction du PC) ne partent plus dans l'archive.
- L'en-tête `Host` est vérifié (fini le « DNS rebinding ») et la plupart des **lectures privées** (appareils, Wi-Fi, PC, sauvegarde, accès…) passent derrière le déverrouillage.
- Le jeton de l'écran local est publié sans risque de lien symbolique, le kiosque Chromium est bridé (pas d'outils de développement, navigation limitée), et les dossiers de médias d'app restent confinés à `/srv/ydz`.
- Le **flux temps réel** (`/api/events`) exige désormais le code lui aussi : il ne laisse plus consulter la tour sans déverrouiller (faille trouvée lors de l'attaque menée sur cette version, corrigée avant publication).

### À faire après l'installation
- **Installe la 1.0.15 à la main une seule fois** (Réglages → Mises à jour → dépose le .zip). Ensuite, les versions suivantes se téléchargent et s'installent toutes seules.
- **Change ton code PIN** pour 6 chiffres ou plus (le bandeau orange en haut te mène au bon endroit).
- **Note la phrase de sauvegarde** affichée dans Réglages → Sauvegarde → « Préparer le PC » : sans elle, une archive chiffrée ne peut pas être restaurée. Elle n'est stockée que sur le Pi.

### Limites connues
- Le terminal web reste joignable sur le réseau local (pour le terminal depuis le téléphone) ; le passer en « 127.0.0.1 seulement » derrière un relais authentifié est documenté mais pas encore automatique.
- La signature des paquets (clé ed25519) est préparée mais pas exigée : la confiance des mises à jour repose sur HTTPS + l'empreinte SHA-256 de l'index.
- Le durcissement complet de ydzd (séparation en service non privilégié + aide root) est documenté ; seule la partie sans risque est appliquée pour ne pas bloquer un montage ou un changement Wi-Fi.
